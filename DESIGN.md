# flipfee — how it works

**Flip fees into cash.** flipfee is a market for the creator fees of pump.fun coins on Solana, sold by the hour.

- **Trader:** buy an hour of a coin's fees. Every trade on that coin during your hour pays you SOL, about every minute.
- **Dev:** sell your coin's next hours of fees and get SOL now. You keep every fee outside the hours you sold.

Live at https://flipfee.cash. This file is the contract the three parts of the code follow: the Solana program
(`program/`), the server (`server/`) and the web app (`app/`). Section numbers are referenced from code comments.

---

## 0. The fact the design is built on: pump.fun fee sharing

- pump.fun (`6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5uBEwF6P`) pays a **creator fee** on every bonding-curve trade into
  `creator_vault = PDA["creator-vault", bonding_curve.creator]`. PumpSwap (`pAMMBay6oceH9fJKBRHGP5D4bD4sWpmSwMn52FMfXEA`)
  pays `coin_creator_fee` into the WSOL account of `PDA["creator_vault", pool.coin_creator]` once a coin graduates.
- Pump Fees (`pfeeUxB6jkeY1Hxd7CsFCAjcbHA9rWtchMGdZ6VojVZ`) adds **fee sharing**: the creator creates
  `sharing_config = PDA["sharing-config", mint]`, and its admin sets up to 10 shareholders (shares sum to 10 000 bps)
  with `update_fee_shares_v2` — **once; the admin is revoked after**. `distribute_creator_fees_v2` (anyone can call it)
  pays the creator vault out to the shareholders; `transfer_creator_fees_to_pump_v2` first sweeps PumpSwap fees of a
  graduated coin into the pump vault.
- Every trade event carries the exact fee: pump `TradeEvent.creator_fee`, PumpSwap `BuyEvent/SellEvent.coin_creator_fee`.

**Consequence.** pump.fun cannot grant a share for a limited time — one split per coin, forever. So a coin joins
flipfee **once**: its dev sets the split to **100% → the coin's flipfee vault**. From then on the flipfee program routes
every fee: to the buyer of the hour while a sold hour runs, to the dev the rest of the time. The step is final on
pump.fun, and the app says so plainly before the dev signs (§1.5).

## 1. Product

### 1.1 The point, in one glance

- Trader: "Buy an hour of a coin's fees. Every trade in that hour pays you SOL."
- Dev: "Sell your coin's next hours of fees. Get SOL now."

### 1.2 The mechanic

| | |
|---|---|
| What you buy | **100% of a coin's creator fees for N hours** |
| Length | **1–12 hours per buy** |
| Start | **now**, or right after the last sold hour (a queue) |
| Price | **one price per hour per coin**, set by the dev (0.01–1000 SOL; suggested from live data) |
| Getting paid | **SOL lands in your wallet by itself**, about every minute |
| Dev setup | **one transaction**, one time |

- Suggested price = 80% of the coin's creator fees in the last hour (fallback: last 6 h ÷ 6).
- How far ahead hours sell: the dev sets 1–48 h (default 24 h).
- flipfee's fee: **5% of each hour sale** (the dev gets 95% at once). Fees outside sold hours: **0%** to flipfee.
- Fees are split **by the second**: each payout interval is shared by how many seconds each hour overlaps it.

### 1.3 What a trader can do

1. **Buy an hour** on a live coin: one tap → Phantom → the hour starts (or queues) → SOL arrives with each trade.
2. **Want** a hot pump.fun coin that is not on flipfee yet (free, after sign-in). Its dev sees how many traders want it.
3. Watch: the board is live without a wallet.

### 1.4 What a dev can do

1. Connect Phantom → "Your coins" lists the pump.fun coins this wallet created, with fees, wants and eligibility (§2.4).
2. **List the coin** (one transaction, §1.5): set a price per hour and how far ahead hours sell.
3. Dashboard: hours sold, SOL received, fees routed to you, the queue, pause/resume, change price.

### 1.5 The one-time listing sheet

- "Your coin's fees go to flipfee from now on."
- "You get every fee outside sold hours. It lands in your wallet."
- "Buyers pay you for each hour. You get 95%."
- "pump.fun allows one fee split per coin. This step is final."
- Button: "List $TICKER" → one Phantom signature.

### 1.6 Screens

- **Board** `/`: a hero that shows the product in three parts — *fees generated by trades* (a hot coin's live trades,
  each with its fee), *gathered in a virtual vault* (an interactive dithered coin vault; drag to spin, tap to flip;
  each real trade sends a coin into it), *and tradable on flipfee* (what the last hour paid, and a 24-hour strip of
  your hour vs the dev's). Then live coins (or, while none is live, the hot coins most wanted to go live), then the
  hottest pump.fun coins with Want and Share.
- **Coin** `/c/<mint>`: header, hour timeline, trade stream, fee stats, buy panel ("Last 6 h paid on average …" —
  a fact, never a promise).
- **Devs** `/dev`, **Me** `/me` (my hours and payouts), **Docs** `/docs` (how it works, with charts and a backtest on
  labelled example data), **Terms**, **Privacy**.

### 1.7 Look and feel: ink on paper, dithered

- Paper `#ECECE7`, sheets `#F7F7F3`, one ink: ultramarine `#1F2BFF` for money, live state and the brand; black for text.
- Dither is the image system: coin images pass through one SVG ordered-dither filter (`app/src/dither/DitherDefs.tsx`);
  the coin mark and the hero vault are ray-cast in code and thresholded against a Bayer matrix (`app/src/dither/coin.ts`).
- Numbers in a dot-matrix face (Doto), labels in Geist Mono, text in Geist. Calm motion; reduced motion shows still frames.

## 2. Architecture

```
program/   Anchor program `flipfee` + client/ (TypeScript: builders, decoders, pump instructions) + keeper/
server/    Node ≥ 22: live pump.fun data, the flipfee index, SSE, Sign-In With Solana, wants, keeper host
app/       Vite + React 19 + TypeScript: board, coin, devs, me, docs; Phantom only
release.sh build → upload → restart → health check
```

Toolchain: Anchor 1.2.0, Solana CLI 4.1.2, Node ≥ 22 (`node:sqlite`).

### 2.1 Program `flipfee` (Anchor)

PDAs: `config = ["config"]`, `coin = ["coin", mint]`, `vault = ["vault", mint]` (a system-owned PDA with no data: the
pump.fun shareholder address that receives the fees).

```rust
Config { admin, treasury, fee_bps /* ≤ 1000, default 500 */, paused, bump }
Coin {
  mint, owner /* the dev */, price /* lamports per hour */, max_ahead /* seconds */, paused,
  last_sync, owner_owed, credited /* Σ owed not yet paid */, windows: Vec<Window> /* ≤ 32, sorted */,
  fees_in, sales, hours_sold, paid_out, …
}
Window { holder, start, end, owed, earned }
```

Instructions:
1. `initialize(fee_bps)` — once, by the upgrade authority (who becomes admin).
2. `register(price, max_ahead)` — the dev. Checks the pump sharing config is active, final (admin revoked) and sends
   100% to this coin's vault, and that the signer is that config's admin. Fees already in the vault are the dev's.
3. `set_terms(price, max_ahead, paused)` — the coin owner.
4. `transfer_owner()` — owner and new owner both sign; the old owner is paid what it is owed first.
5. `buy(hours, max_price, max_start)` — a buyer. Syncs first; the hour starts now or after the last sold one; pays
   `price × hours`: 95% to the coin owner, 5% to the treasury; queues a window.
6. `crank()` — anyone. **Sync**: new lamports in the vault are allocated over `(last_sync, now]` to windows by overlap
   seconds, the rest to the owner. **Pay**: owed SOL goes to the owner and to each holder passed in; finished, paid
   windows are dropped.
7. `set_config(fee_bps, paused)`, `set_admin(new_admin)` — admin. The admin has **no path to vault money**.

Invariants (tested): vault lamports ≥ rent + credited; everything that arrives is allocated; a window gets exactly its
overlap share; money only moves to the coin owner, the hour buyers and the treasury (sales fee only); repeated cranks
are idempotent; u128 arithmetic.

`client/` — PDA helpers, account decoders (Config, Coin, Window, pump BondingCurve, AMM Pool, SharingConfig),
instruction builders for flipfee **and** the pump instructions the app and keeper need, an `eligibility(conn, mint,
wallet)` check, and full-transaction helpers (`buyTx`, `connectCoinTx`, `crankTx`). SOL-paired coins only.

`keeper/` — every ~60 s for each listed coin: sweep PumpSwap fees (graduated coins), distribute the pump vault to the
flipfee vault, then `crank` with the owner and the live/ended holders. Runs inside the server with `KEEPER=1`, or as a CLI.

### 2.2 Server

Port 5295, `node:sqlite`, Server-Sent Events, Sign-In With Solana, sessions.

- **Live trades with exact creator fees** for tracked coins: RPC `logsSubscribe` per bonding curve and PumpSwap pool,
  PumpPortal for launches and migrations. Tracked = listed coins + the hottest coins (pump.fun API, DexScreener),
  capped by the RPC budget.
- **Per-coin metrics**: creator fees 1m/10m/1h/6h/24h, trades, volume, price, market cap, age; coin names are moderated
  (hate slurs masked, such coins kept off the board).
- **flipfee index**: Config + every Coin account, program events; holders, queues, payouts, totals.
- **Wants**: one per wallet per coin.

API: `GET /api/board`, `GET /api/coin/:mint`, `GET /api/dev/:wallet`, `GET /api/me/:wallet`, `GET /api/stream` (SSE),
`POST /api/auth/nonce|verify`, `POST /api/want`, `GET /api/health`.

### 2.3 App

Vite + React 19 + TypeScript. **Phantom only** (connect, deep link to Phantom's in-app browser on phones, SIWS).
Transactions are built with `client/`, simulated, then signed in Phantom. First paint from the `/api/board` snapshot,
then live over SSE. Page changes use view transitions (a coin's picture and ticker travel to its page).

### 2.4 Eligibility of a coin

| State on chain | Shown | Action |
|---|---|---|
| no sharing config, wallet = creator | Ready | List = create config + set split + register (one tx) |
| sharing config not final, wallet = admin | Ready | List = set split + register (one tx) |
| split already 100% to the flipfee vault, not registered | One step left | Register |
| split final and pointing elsewhere | Fee split locked | Want / Share only |
| USDC-paired coin | SOL coins only for now | — |
| wallet is not the creator/admin | — | Want / Share |

## 3. Testing

- **Program**: LiteSVM tests with the real mainnet pump, pump_amm and pump_fees binaries (`program/fixtures/mainnet`):
  create a coin, trade, set the split, register, buy hours, trade during and after the hour, distribute, crank;
  exact time-weighted splits, payouts, idempotence, every error path, plus a randomized model test.
- **Client**: unit tests and a localnet run. **Server**: unit and integration tests. **App**: Playwright against a
  local stack with an injected Phantom-compatible provider; screens at 1440 and 390 px.
- **Copy gate**: `npm run copy` in `app/` keeps all UI text at a grade-3 reading level, affirmative, with no hype.
